# Промт: уникальный визуал навыков, пилот — друид

Скопировать всё, что ниже черты, в новую сессию Claude Code на этом репозитории
(ветка с эффектами — `claude/happy-pascal-ts4x0e` или та, куда она слита).

---

Задача: навыки должны выглядеть каждый по-своему, а не набором одинаковых
колец и вспышек. Хватающие корни — это корни, которые правда вырастают из
земли и держат цель; цепь колдуна — цепь; знамя рыцаря — знамя. Сценарий
каждого навыка уже написан: `docs/vfx/skill-visuals.md`. Твоя работа — сделать
для этого инструменты и **полностью перевести друида** (раздел 3 сценария).
Остальные классы — следующими задачами, по готовому образцу.

## Прочитай до начала

- `docs/vfx/skill-visuals.md` целиком: правила (раздел 0), библиотека
  объектов (1), состояния на цели (2), друид (3).
- `SPEC.md`, раздел M14, особенно абзацы про эффекты навыков, «каждый видит
  один вид», «у игрока с модом нет ни одной ванильной частицы», «граница —
  это радиус выборки», «зоны растут от skill_radius», «контент в папке
  плагина следует за версией плагина».
- `client-mod/README.md`, раздел «Эффекты навыков».
- Код эффектов: плагин — `skill/FxEvent`, `skill/SkillRuntime` (частицы,
  зоны, урон), `platform/BukkitSkillWorld`, `platform/FxBroadcaster`,
  `net/FxMessage`, `net/StateCodec`; мод — `FxEffects`, `FxKinds`, `FxStyle`,
  `FxDraw`, `FxMotes`, `FxGround`.

## Решения владельца

- **3D рисует мод сам.** Объекты — модели ванильных блоков и предметов
  (`mangrove_roots`, `vine`, `chain`, `shield`, `white_banner`, черепа и т.д.)
  и простая своя геометрия, нарисованные в `RenderLevelStageEvent` через
  `BlockRenderDispatcher` / `ItemRenderer` со своими преобразованиями. **Ни
  одной новой записи в реестрах** — ни `ParticleType`, ни `EntityType`, ни
  блоков: причина записана в шапке `FxDraw`. Display-сущности сервера не
  используем.
- **Слои:** объекты в мире, эффекты на теле, экранные эффекты, свои звуки.
- **Пилот — друид:** все шесть навыков и состояния, которые они вешают
  (`root`, `stun`, `growth`, `wither`, `bark_guard`, `slowed`, яд).

## Что построить

### 1. Объекты в мире (мод)

Библиотека из раздела 1 сценария — для пилота нужны: **корень**, **лоза**,
**цветок/бутон**, **кора**, **трещина**, **волна земли**, **дым/пыль**. У
каждого объекта фазы «вырасти → держать → уйти» и параметры (длина, толщина,
изгиб, куда тянуться, сколько держать). Корень — цепочка сегментов вдоль
сплайна от точки в земле к цели, каждый сегмент — модель блока, повёрнутая
по касательной; растёт по длине, а не появляется целиком. Проверь, как в
NeoForge 21.1 рисовать модель блока в произвольной матрице без мира
(`renderSingleBlock` или `ModelBlockRenderer` с `PoseStack`), и как это
вписывается в текущий `FxDraw` (у него свои пачки по текстуре и аддитивное
свечение — объекты рисуются обычным непрозрачным/вырезанным проходом, свечение
поверх).

### 2. Сцены навыков (мод)

Сейчас у `fx` есть только стиль (`FxStyle`: вид, цвета, сроки). Нужна
**сцена**: код, который по событию собирает несколько объектов, искры, звук
и экранный эффект по сценарию. Предложи, как связать: например, каталог
`fx id → сцена`, а сцена получает то же событие (`Burst`, `ZoneOn`, …) с
числами сервера. Неизвестный `fx` по-прежнему рисуется ролью класса —
ничего не ломается.

**Граница — правда.** В каждой сцене с областью остаётся читаемая черта ровно
на радиусе из события; корни, лозы, облака упираются в неё. Это проверяется
тестом (см. «Проверка»).

### 3. Состояния на существах (плагин + мод)

Сейчас мод знает только статусы самого игрока. Чтобы корни держались на
ногах цели ровно столько, сколько висит `root`, нужен новый вид события:
«на существе N статус S, наложил M, срок T тиков (остаток R), стаков K» и
«статус снят». Шлётся игрокам с модом в радиусе, как эффекты; подошедший позже
получает текущие статусы с остатком — по образцу того, как `FxBroadcaster`
досылает зоны. `Protocol.VERSION` → 10, копия `net/` в мод, `ProtocolCopyTest`
и тест кодека в оба конца.

Мод рисует состояния по таблице раздела 2 сценария. Для пилота — `root`,
`stun`, `slowed`, яд (ванильное зелье poison — проверь, приходит ли он
статусом или нужен отдельный путь), `growth`, `wither`, `bark_guard`.

### 4. Экранные эффекты (мод)

Тряска камеры, виньетка/рамка, вспышка по краям. Правила — раздел 0
сценария: мягко, коротко, видит только тот, кого касается (мод решает сам по
своей позиции и радиусу из события), выключается одним переключателем в
настройках мода (клиентский конфиг NeoForge) и сам выключается на «Частицы:
минимум». Для крита ударившего — в событие `Hit` нужен номер ударившего.

### 5. Звуки (мод + плагин)

Свои звуковые события в `assets/rpgcore/sounds.json`. Своих `.ogg` нет —
событие собирается из ванильных звуковых файлов (несколько вариантов, высота,
громкость); `.ogg` не синтезировать и не выдумывать. **Дважды никто не
слышит:** игрок с модом получает звук сцены, а ванильный звук действия
`sound` ему не уходит; игрок без мода слышит ванильный, как сейчас. Как
связать `sound` в YAML со сценой — предложи (например, сцена объявляет, что
звучит сама, и платформа не шлёт ванильный звук моддерам для этого шага).

### 6. Контент друида (плагин)

У навыков друида — свои `fx` вместо ролей класса (`druid_roots_grasp`,
`druid_ivy_lash`, …), где сценарию нужно своё. Механику навыков не менять:
если сценарий требует того, чего механика не делает, — спроси владельца, а
не правь баланс.

## Ограничения

- Стиль кода — как в проекте: комментарии по-русски и объясняют «почему»;
  Bukkit только в `platform/`; `DependencyDirectionTest` зелёный.
- Производительность: соблюдать «Частицы» (всё / меньше / минимум), дальше
  `NEAR` — проще, вне кадра — никак; объекты в пуле с жёстким пределом; при
  перегрузке первыми режутся украшения, граница и состояния — никогда.
  Двадцать друидов с корнями в одной точке не должны ронять кадр.
- Игрок без мода видит ванильный запасной вид, как сейчас.
- Ни один эффект не роняет игру: ошибка снимает только эту сцену.

## Порядок работы

1. Изучи код и сценарий, пришли **план**: как рисовать модели блоков без
   реестра (с выводом по исходникам NeoForge 21.1), формат событий состояний,
   как связаны сцены и `fx`, как устроены звуки без дублей, как настраиваются
   экранные эффекты; раскадровку каждого навыка друида по тикам (замах, удар,
   след) и бюджет на кадр. Код — после одобрения.
2. Инструменты: объекты, сцены, состояния, экран, звук — с тестами.
3. Друид целиком.
4. Обнови `SPEC.md` (M14) и `client-mod/README.md` («как сделать сцену
   навыку»), отметь в `docs/vfx/skill-visuals.md`, что сделано.

## Проверка

- Тесты плагина: событие состояния уходит при наложении и снятии, срок в нём
  — настоящий срок статуса со статом длительности; подошедший позже получает
  статус с остатком; кодек в оба конца.
- Тест геометрии сцен (без Minecraft, чистая математика): ни одна точка
  корней, лоз и облака не выходит за радиус события; граница стоит ровно на
  радиусе.
- `./gradlew build` и `./gradlew -p client-mod build`.
- Ты не можешь запустить игру — скажи это прямо и дай владельцу короткий
  список, что проверить глазами: `/rpg content update` (контент на сервере),
  `/rpg area`, каждый навык друида через `/rpg cast <навык> raw`, второй
  клиент без мода, настройка экранных эффектов.

В конце — короткий отчёт: что сделано, что проверено, что нет и почему,
открытые вопросы, и что нужно, чтобы перевести следующий класс.
